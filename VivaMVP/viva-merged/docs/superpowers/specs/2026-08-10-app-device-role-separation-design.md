# 앱·디바이스 역할 분리 + 연결 상태 표면화

작성: 2026-08-10

## 문제

1. **눈이 두 군데다.** 디바이스(`pi-server/eyes.py`)가 진짜 얼굴인데, 앱도 `EyeAnimation`을 Home·Camera·Processing·Board·Character 뷰 전부에 띄운다. `EyeAnimation.tsx:24` 주석이 이미 인정한다 — "로봇 마이크 모드에선 학생이 로봇 얼굴을 본다, 폰 눈은 대상이 아니다." 역할이 갈라지지 않아 제품 정체성이 흐리다.
2. **연결 상태를 아무도 모른다.** liveness 판단이 세 조각이다 — `piReadyRef`(HTTP `/health`, idle 복귀 때만), 눈 WS(3초 자동 재접속, 관찰자 없음), 웨이크 WS(재시도 없음). "로봇이 오프라인"을 화면에 보여주는 곳이 없다.
3. **끊기면 조용히 폰으로 폴백한다.** 학생이 로봇을 보고 있는데 소리가 갑자기 폰에서 나온다. 사용자가 끊김을 인지할 방법이 없고, 복구 행동(전원·와이파이·재부팅)을 안내받을 곳도 없다.

## 합의된 결정

| 축 | 결정 |
|---|---|
| 역할 | 앱 = 보조 칠판(풀이 이미지·자막·세션 기록·연결 상태). 디바이스 = 얼굴(눈)·마이크·스피커·카메라 |
| 모드 | 실행 시 항상 **디바이스 모드**. 홈 토글로 **APP 모드**(폰 단독 — 마이크·스피커·눈 전부 폰, Pi 완전 무시) 전환 |
| 앱 눈 | 디바이스 모드에서 숨김. APP 모드에서만 `EyeAnimation` 표시 |
| 세션 중 끊김 | 일시정지 + 안내 오버레이 + 선택(자동 재연결 / APP 모드로 계속 / 종료) |
| 홈 | 미니멀형 — 상태 칩 + "비바야" 안내 중심 |
| 아키텍처 | ConnectionMonitor 모듈 싱글턴, `/health` 단일 판정자 |

## 설계

### 1. 모드 시스템 — `useAppMode`

- `src/hooks/useAppMode.ts` 신설, `useSolveMode` 패턴 그대로. 값 `'device' | 'app'`, 초기값 `'device'`. 영속화 없음 — 실행마다 디바이스 모드로 시작한다.
  <!-- ponytail: 영속화 생략. 디바이스 없는 사용자가 늘면 AsyncStorage 한 줄 추가 -->
- 현재 흩어진 로봇 경로 플래그(`robotMic`·`robotSpeaker`·`robotAudio` prop, `tts.service.ts`의 모듈 불리언)를 전부 **모드에서 파생**시킨다. 단일 소스: `mode === 'device'`.
- APP 모드 전환 시: eyeSync `stop()`(존재하지만 미호출이던 API), 웨이크 Pi 스트림 미사용(폰 마이크 경로는 `wakePiSource` 분기로 이미 존재), ConnectionMonitor 정지, 진행 중 Pi 녹음·재생 정리(`/record/stop`·`/play/stop` best-effort).
- 토글 UI: 홈 상단. 세션 진행 중에는 토글 노출 안 함 — 모드 전환은 홈과 끊김 오버레이에서만.

### 2. ConnectionMonitor — `connectionMonitor.service.ts`

- `eyeSyncService`와 같은 모듈 싱글턴 + `usePiConnection()` 훅.
- 상태: `connected | connecting | disconnected`. `connecting`은 첫 판정 전과 재프로브 중에만.
- **판정 규칙: `GET /health` 성공 여부가 유일한 진실.** 5초 주기 폴링(디바이스 모드에서만).
- 보조 신호는 판정하지 않고 **즉시 재프로브만 트리거**한다: 눈 WS `onConnectionChange`(미사용 API 활용), piBridge 호출 실패(`reportFailure()` 한 줄을 catch 경로에 추가). 채널별 상태를 UI에 노출하지 않는다 — 파편화 재생산 방지.
- 기존 `piReadyRef`(App.tsx:130)는 monitor 구독으로 대체.

### 3. 화면 재편

**홈 — 디바이스 모드 (미니멀형):**
상단 상태 칩(● 연결됨 / 연결 중 / 연결 안 됨) + 모드 토글. 중앙 "비바야"라고 불러보세요. 하단 시작·기록 버튼.
`disconnected`면 중앙을 연결 안내 카드로 교체: ① 디바이스 전원 확인 ② 폰과 같은 와이파이인지 확인 ③ 전원을 뽑았다 다시 꽂기(재부팅). 이때 세션 시작 불가, 웨이크 리스닝은 폰 마이크로 유지하지 않음(디바이스 모드의 웨이크는 로봇 마이크 전제).

**홈 — APP 모드:** 현행 HomeScreen 유지 — 눈 중앙 + push-to-talk 마이크.

**대화 화면 — 디바이스 모드:** 눈 제거. 칠판(`BoardView`) + 자막 확대가 주인공. 칠판 없는 구간은 `CharacterView` 대신 자막 중심 레이아웃 — 기존 `getStatusSlot()`(리스닝 가이드·자막·로딩 닷 중 정확히 하나) 로직 재사용. 눈 상태 **송신**(eyeSync, D-42 매핑)은 그대로 — 이 스펙은 앱 쪽 눈 **표시**만 걷어낸다.

**대화 화면 — APP 모드:** 현행 유지(`CharacterView` 눈 포함).

**ProcessingView·CameraScreen:** 디바이스 모드에선 눈 대신 로딩 표현(`LoadingDots` 중심).

**끊김 오버레이 — 디바이스 모드 세션 중:** monitor가 `disconnected`로 바뀌면 세션 위에 전체 오버레이.
- 자동 재연결 중 스피너(별도 재시도 로직 없음 — monitor 폴링이 계속 돌고, 오버레이는 상태를 구독만 한다)
- 홈과 동일한 체크리스트 3항목
- [APP 모드로 계속] → `mode='app'` 전환, 마이크·스피커·자막 폰으로 이어감(세션 상태 유지, 기존 폴백 경로 재사용)
- [세션 종료] → 기록 저장 후 `handleResetToIdle`
- `connected` 복귀 시 오버레이 자동 해제, 진행 중이던 턴은 재시작(`resumeSession` 인프라 재사용)

### 4. 디바이스 쪽 끊김 표시 — `eyes.py`

- WS 클라이언트 0 상태가 30초 지속 → '연결 끊김' 표정: 잠자는 눈(반쯤 감김) + 글리프(기존 `MARKS` 시스템에 항목 추가). 클라이언트 재접속 시 즉시 복귀.
- "마지막 클라이언트 끊기면 idle 리셋"(2026-08-07) 패턴의 확장이다. 앱이 죽어서 못 보내는 상황은 Pi가 스스로 판단할 수밖에 없으므로 single-writer 원칙(2026-08-07 발화 종료 스펙의 기각 사유) 위배가 아니다 — writer가 갈라지는 게 아니라 writer 부재 시의 기본값이다.
- 30초 유예는 폰 화면 잠깐 꺼짐·앱 전환으로 표정이 요동치는 것을 막는다.

## 기각한 대안

- **하트비트 WS 채널 신설** — 실시간성은 좋지만 Pi 서비스·프로토콜 추가. 폴링 5초면 UX 충분. 과설계.
- **UI가 채널별 상태를 직접 조합** — 지금의 3파편 문제를 화면 수만큼 복제하는 것.
- **앱 눈 완전 제거** — APP 모드에서 VIVA 페르소나가 사라진다. 폰 단독 사용자에게 얼굴은 필요하다.
- **끊김 시 자동 폰 폴백(현행)** — 학생이 로봇을 보는데 소리가 폰으로 점프. 인지 불가·혼란. 폴백은 사용자가 [APP 모드로 계속]을 눌렀을 때만.
- **연결 상태 4단계 이상(부분 연결 등)** — 눈 WS만 죽고 HTTP 살아있는 경우를 별도 상태로 노출하면 UI만 복잡. 재프로브 트리거로 흡수.

## 에러 처리

- 세션 중 감지 경로: piBridge 호출 실패 → `reportFailure()` → 즉시 `/health` 프로브 → 실패 시 `disconnected` → 오버레이. 성공 시(카메라만 죽은 경우 등) 상태 유지 — "camera dead ≠ Pi dead"(App.tsx:274) 원칙 계승.
- APP 모드 전환 직후 Pi 쪽 자원 정리 실패는 무시(best-effort) — Pi 재부팅 시 어차피 초기화.
- 오버레이 중 TTS·녹음 진행 상태: 일시정지 시 `/play/stop` 시도, 폰 오디오는 즉시 정지.

## 테스트

- `connectionMonitor` 단위 테스트: 프로브 성공/실패 전이, 트리거 재프로브, APP 모드 정지.
- `useAppMode` 파생 플래그 테스트: 모드별 robotMic/robotSpeaker/eyeSync 활성 여부.
- `eyes.py --selftest`에 disconnected 상태 불변식 추가, `--window` 키 6번으로 수동 확인.
- 기존 E2E 하네스(docs/e2e-runs)는 APP 모드 경로로 그대로 유효 — 디바이스 모드 신규 경로는 실기기 검증 항목으로 process.md에 기록.
