# 판서: 전사 1회 + 오버레이 설계

날짜: 2026-07-29 · 브랜치: fix/board-accuracy-pi-retake · 승인: "첫 진입 시 항상 재작화 1회"

## 배경

현행 판서는 힌트 턴마다 이미지 모델을 부른다(장당 ~15초/$0.101, 세션 상한
15장, 매 턴 직전 판서 1932KB 재업로드). hallucination 의 근본 원인은 "생성
모델에게 문제지를 다시 그리게 하는 것" 인데, 그 재작화가 턴마다 반복된다.
그라운딩+사후검증(D-20)은 완화지 제거가 아니다.

## 결정

**재작화는 세션당 1회(순수 전사)로 줄이고, 힌트 표시는 앱이 전사본 위에
직접 그리는 오버레이로 바꾼다.** 이미지 모델 호출은 세션당 최대 2장이 된다:
전사 1장 + (필요 시) SOLVE_STAGE 전체 풀이 1장.

| | 현행 | 변경 후 |
|---|---|---|
| 힌트 턴 판서 지연 | ~15초 | 0초 (EVAL 응답에 좌표 동봉) |
| 세션 이미지 비용 | 최대 $1.52 (15장) | ~$0.20 (최대 2장) |
| 환각 표면적 | 매 턴 재작화 | 전사 1회 (검증됨) |
| EVAL 업로드 | 문제 사진 (+판서 수정 시 1932KB) | 다운스케일 전사본 1장 고정 |

## 구성

### 1. 전사 1장 (세션 시작)

- 기존 `generateVerifiedBoardImage` 그대로 사용하되 boardPrompt 를 고정
  전사 지시(`TRANSCRIPTION_INSTRUCTION`: 힌트/강조/화살표 일절 금지, 전사만)로
  전달. Gemini 가 준 board_prompt 는 힌트 턴에서 더 이상 사용 안 함.
- onDraft 즉시 표시 + 백그라운드 검증/재생성(기존 유지). 검증은 전사
  충실성만 보게 되어 오히려 단순·정확해진다.
- 생성 직후 다운스케일(폭 ~1280, JPEG q80) 1회 → 이 표현 하나를 표시·EVAL
  컨텍스트·SOLVE 수정 base 에 공용으로 쓴다 (2K 원본을 매 턴 나르지 않는다).
  다운스케일은 기존 설치된 이미지 리사이즈 유틸 사용(없으면
  expo-image-manipulator 추가).

### 2. 힌트 턴 = 오버레이 (이미지 모델 호출 없음)

- `RESPONSE_SCHEMA` 에 `annotations` 배열 추가:
  `{ type: 'circle'|'underline'|'arrow'|'question_mark'|'label', box_2d: [ymin,xmin,ymax,xmax] 0~1000, text? }`
- 좌표 기준은 "첨부된 판서 이미지"(= 전사본). EVAL 턴의 첨부 이미지를 원본
  사진 → 전사본으로 교체하므로 좌표와 화면이 정확히 일치한다.
- 렌더는 순수 RN View/Text (점선 테두리 원, 밑줄 바, "?" 글리프, "→" 글리프,
  짧은 라벨). react-native-svg 같은 새 네이티브 의존성 없음 → iOS 재빌드
  불필요. 색은 앱 코드가 강제(#369B75 계열) — 금지 요소가 구조적으로 불가능.
- 매 턴 annotations 는 직전 오버레이를 **교체**한다 (실제 과외에서 이전
  표시를 지우고 지금 볼 곳을 가리키는 문법). box_2d 에는 ±수% 오차를
  감안한 여유 패딩을 두고 그린다.
- 첫 분석 턴(첨부가 원본 사진, 전사본 아직 없음)은 annotations 비움 —
  첫 힌트는 음성 + 전사본 등장 자체로 충분. 오버레이는 2턴째부터.

### 3. SOLVE_STAGE 전체 풀이 (이미지 1장)

- 단계별 수식 전개는 오버레이로 부족 → 기존 이미지 수정 경로 유지:
  전사본을 base 로 board_prompt(풀이 시각화) 1회 생성. revealAnswer 분기
  그대로.

### 4. 프롬프트 계약 변경 (system_prompt.ts)

- `ANNOTATION_POLICY` 신설: annotations 채우는 법, 좌표계, 절제(현재 힌트가
  지목하는 것만, 0~3개). `HintPolicyContext.boardAttached` 플래그가 참일
  때(=EVAL 턴, 전사본 첨부)만 포함.
- `BOARD_PROMPT_POLICY` 개편: 힌트 턴은 board_update_needed=false +
  board_prompt="" 고정(이미지 재생성 요청 금지), SOLVE_STAGE 만
  board_update_needed=true + board_prompt 허용.

### 5. 재촬영

새 사진 → 재전사 1장(기존 Tier1/2/로봇 재촬영 사다리 그대로). 오버레이
좌표 기준도 새 전사본으로 자연 갱신.

## RAG 비범위 결정

기존 문제 데이터셋 RAG 는 이 스펙에 안 묶는다. 이미지 정확도의 원인(이
학생 사진의 전사 환각)에는 직접 효과가 없고, 효과 있는 지점(교재 매칭 시
problem_facts 대체, 풀이 텍스트 품질)은 별도 피처(`feature/rag`)로.
이번 구조에는 나중에 "매칭 시 전사 ground truth 대체" 한 줄로 얹힌다.

## 리스크

- EVAL 이 원본 사진 대신 전사본을 본다 → 전사 오류가 평가에 전파될 수
  있음. 완화: 전사는 검증(D-20)을 거친 이미지다. 학생 손풀이 채점 등 새
  사진이 필요한 경로는 기존대로 재촬영 사다리를 탄다.
- box_2d 정밀도 ±수% → 오버레이에 여유 패딩, 정밀 지시가 필요한 경우
  label 텍스트로 보완.
- 전사본 다운스케일(1280px)이 SOLVE 수정 base 로 쓰임 → 풀이 이미지 선명도
  소폭 하락 가능. 실기기에서 확인 후 필요 시 원본 2K 를 SOLVE base 전용으로
  보관.

## 비범위

- RAG 결합 (위)
- 오버레이 애니메이션/터치 인터랙션
- 힌트 턴의 이미지 모델 재생성 경로 완전 삭제는 하지 않는다 — SOLVE 경로가
  같은 코드를 쓴다. 상한 15 는 유지(자연히 ≤3장).
