# WiFi 프로비저닝 (QR + 로봇 카메라) 설계

2026-08-11. 목적: **로봇 초기 세팅(언박싱)과 네트워크 변경**을 사용자가 앱만으로 끝내게
한다. 데모 장소의 다른 WiFi 대응은 부산물로 따라온다. 2026-08-11-disconnect-fault-ux
스펙 §5 에서 보류했던 항목의 정식 설계.

## 0. 명칭 규칙

사용자 노출 문구에서 앱 지칭은 항상 **"VIVA 앱"** (그냥 "앱" 금지). 기존 연결 끊김
화면 문구도 "VIVA 앱과 / 연결이 필요합니다" 로 통일 변경한다.

## 1. 핵심 구조 — 로봇 화면 2계층 진단

로봇은 자기 WiFi 상태를 정확히 알므로, "왜 안 되는지"를 화면이 스스로 갈라 보여준다.
사용자는 로봇 화면만 보면 다음 행동이 정해진다.

| # | 조건 | 화면 | 카메라 | 비고 |
|---|------|------|--------|------|
| P1 | 저장된 WiFi 없음 (첫 부팅) | "VIVA 앱에 표시된 / QR 코드를 보여주세요" + QR 스캔 아이콘 | 켬 (스캔) | **대기 없이 즉시** — 시도할 네트워크가 없다 |
| P2 | 저장된 WiFi 있는데 실패: 부팅 후 30초 초과 / 비번 오류 / 운영 중 끊김 3분 지속 | "WiFi 연결에 실패했어요 / VIVA 앱의 디바이스 설정 가이드에 따라 / QR 코드를 스캔해주세요" + QR 아이콘 + **재연결 버튼** + 하단 작게 재연결 상태 | 켬 (스캔) | 백그라운드 자동 재연결 병행. 공유기 복구가 먼저면 그쪽이 이기고, QR 이 먼저면 새 등록이 이긴다 |
| D | WiFi 정상, VIVA 앱만 부재 | 기존 폰+슬래시 "VIVA 앱과 / 연결이 필요합니다" | 끔 | 이번에 만든 화면 그대로 (문구만 §0 반영) |

P1/P2 는 문구·버튼 유무만 다르고 스캔 로직 동일 — 렌더 분기 하나.

임계값 상수 (실측 후 조정 전제): 부팅 유예 `BOOT_GRACE_S = 30`, 운영 중 끊김
`RUNTIME_LOSS_S = 180`, 상태 폴링 5초.

## 2. QR 페이로드

표준 WiFi QR 포맷 그대로: `WIFI:T:WPA;S:<ssid>;P:<psk>;;`

- 특수문자 `\ ; , : "` 백슬래시 이스케이프 (표준 규칙).
- 커스텀 JSON 없음 — 표준이라 폰 기본 카메라로도 페이로드 검증 가능, 로봇 발견은
  기존 mDNS(viva.local) 담당이라 로봇 정보 불필요.
- 비번은 QR 표시 중에만 메모리에 존재. 앱에 저장하지 않는다.
- 페이로드가 작아 QR 버전 낮음(~29×29 모듈) — 고정초점 카메라 인식 마진 확보.

## 3. Pi 쪽 — 새 서비스 `provision.py` (`viva-provision.service`)

역할: WiFi 상태 감시 → 스캔 모드 진입/이탈 → QR 디코드 → 네트워크 등록 → 터치 처리.

- **상태 감시**: 5초 폴링. NetworkManager 기준 `nmcli` 로 저장 연결 유무·연결 상태
  확인. 저장 연결 0개 = P1 즉시. 있으면 부팅 30초 유예 / 운영 끊김 180초 유예 후 P2.
- **화면 지시**: eyes.py 에 로컬 WS 클라이언트(`ws://localhost:8787`)로 접속해
  `{"eyeState": "provision_new" | "provision_fail"}` 푸시. 기존 프로토콜 재사용,
  새 IPC 없음. 이탈 시 WS 를 끊으면 eyes.py 는 기존 규칙대로 (앱 붙을 때까지
  disconnect 화면 → 곧 VIVA 앱 연결).
- **스캔**: picamera2 640×480, 2~3fps, pyzbar 디코드. Zero W CPU 충분. 카메라 가동
  중 화면 깜빡임(SDRAM 대역폭 경합, README 기록)은 프로비저닝 중 한정으로 감수.
- **적용**: 디코드 성공 → `nmcli device wifi connect <ssid> password <psk>`.
  성공: 카메라 끄고 스캔 모드 이탈. 실패(비번 오류 등): "비밀번호를 확인해주세요"
  상태 몇 초 표시 후 재스캔.
- **재연결 버튼 (P2)**: 패널 터치 지원 확인됨(USB). `evdev` 로 터치 이벤트 읽어
  버튼 영역 탭 시 즉시 재연결 시도 + 화면에 시도 중 피드백. 자동 재연결도 병행이라
  버튼은 수동 즉시 트리거 + 안심용. 터치는 provision.py 가 읽는다 (eyes.py 는
  렌더 전용 유지).
- **카메라 충돌 없음**: 스캔 모드 = WiFi 다운 = app.py 촬영 요청이 도달할 수 없음.
- **전제**: Pi OS bookworm (NetworkManager). 배포 시 `nmcli --version` 확인,
  bullseye 면 적용 함수 하나만 `wpa_cli` 로 교체.

새 apt 의존성: `python3-pyzbar python3-evdev` (README 설치 절 추가).

### eyes.py 변경

- 상태 2종 추가: `provision_new`(P1) / `provision_fail`(P2). disconnect 화면과 같은
  베이크 패턴 (4x 슈퍼샘플, 한글은 `_load_kr_font`).
- P1: QR 스캔 아이콘(QR 모서리 프레임 + 중앙 사각) + 2줄 문구.
- P2: 3줄 문구 + 재연결 버튼(원형 화살표 아이콘 + "재연결" 라벨, 탭 영역은 여유
  있게) + 하단 소형 "재연결 시도 중…" 상태 라인.
- 기존 disconnect 문구 "VIVA for Device 앱과" → "VIVA 앱과" 변경 (§0).

## 4. VIVA 앱 쪽

- **디바이스 설정 가이드**: 로봇 연결이 끊기면 지금 ConnectionGuideCard 자리가
  설정 가이드로 진화. 기존 점검 항목(전원/같은 WiFi/재시작) 유지 + 새 항목
  "로봇 화면에 QR 안내가 보이나요?" + **"WiFi 등록하기"** 버튼.
- **WifiProvisionScreen** (새 화면): 가로 화면에서 왼쪽은 3단계 안내, 오른쪽은
  QR/입력 카드로 나눈다. 시작 시 현재 연결 WiFi의 SSID를 best-effort로 채우고,
  실패하면 같은 입력칸을 비운 채 둔다. 비밀번호는 OS가 앱에 제공하지 않으므로
  사용자가 입력한다. QR 단계는 "1. 스마트폰을 WiFi에 연결하거나 휴대용 핫스팟을
  켠다. 2. VIVA 디바이스 전원을 켠다. 3. 옆 QR 코드를 VIVA 디바이스에 보여준다."
  순서로 고정한다.
- **SSID 권한**: `@react-native-community/netinfo`로 SSID만 읽는다. iOS는 Access
  WiFi Information entitlement와 위치 권한, Android는 위치 권한이 있어야 하며,
  거부·셀룰러·개인용 핫스팟 호스트 모드에서는 수동 입력으로 폴백한다. 비밀번호
  추출·저장·전송은 구현하지 않는다.
- **연결 가이드 레이어**: 끊김 가이드가 보이는 동안 하단 마이크·세션 버튼을
  렌더하지 않는다. 프로비저닝 화면은 최상위 레이어라 상태 칩과 모드 토글도 가린다.
- **QR 렌더**: `qrcode-generator` (순수 JS, 의존성 0) + 행별 run-length View 렌더.
  react-native-svg 등 새 네이티브 모듈 없음 — prebuild 불필요.
- **성공 감지**: QR 화면이 connectionMonitor 구독, connected 엣지에서 체크
  애니메이션 후 자동 복귀. 별도 확인 폴링 없음.

언박싱 플로우 (별도 온보딩 화면 없이 성립):

```
전원 켬 → 로봇: P1 "QR 코드를 보여주세요"
VIVA 앱 설치 → 디바이스 모드 → 로봇 못 찾음 → 디바이스 설정 가이드
"WiFi 등록하기" → SSID/비번 → QR 풀스크린 → 로봇에 비춤 → 연결 완료
```

## 5. 에러 처리 / 폴백

- 스캔 30초+ 미인식: 화면에 "조금씩 가까이/멀리 움직여보세요" 힌트 줄 추가.
- 어두운 방: 폰 화면 자체 발광이라 무관 (오히려 유리).
- 비번 오류 QR: P2 의 "비밀번호를 확인해주세요" 경로. 자동 재스캔 복귀.
- 고정초점 거리 마진: 실기기 캘리브레이션 항목 (§7).
- provision.py 죽음: systemd `Restart=always`. eyes.py 는 WS 클라이언트가
  사라지면 기존 disconnect 규칙으로 수렴 — 화면이 굳지 않는다.

## 6. 테스트

- 앱: 페이로드 이스케이프 단위 테스트 (특수문자 SSID/비번), SSID 자동 채움의
  권한/실패 폴백, WifiProvisionScreen 상태 전이(입력→QR→connected 성공),
  가이드 카드의 등록 버튼·가이드 중 하단 버튼 미노출.
- Pi: selftest 에 P1/P2 프레임 비공백 검증 + 고정 QR PNG 디코드 검증 (카메라
  없이 pyzbar 경로 확인). 터치 좌표→버튼 판정 단위 검증.
- 실기기 검증 항목: process.md §2 에 기록 (스캔 거리, nmcli 적용, 터치 존).

## 7. 구현 순서 (계획 문서에서 상세화)

1. 앱: 페이로드 생성 + QR 렌더 + WifiProvisionScreen + 가이드 카드 개편
2. Pi: eyes.py P1/P2 화면 + provision.py (감시/스캔/적용/터치)
3. README 설치 절 + 실기기 캘리브레이션

## 8. 검토한 대안 (기각 사유)

- **폰 핫스팟 사전 등록**: 코드 0줄로 데모는 해결되나 제품 기능(사용자 초기 세팅)
  이 목적이라 기각. 데모 비상용으로는 여전히 유효한 수동 폴백.
- **SoftAP**: Pi Zero W 단일 라디오로 AP↔STA 전환 관리 복잡, 폰 쪽 WiFi 전환도
  iOS entitlement 필요. 기각.
- **BLE**: 앱·Pi 양쪽 신규 스택 최다. 기각.
