# 앱 분리 (폰 단독판 / 디바이스 연동판) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 하나의 앱(런타임 모드 토글)을 두 개의 스마트폰 앱 — 폰 단독 체험판 / 디바이스(라즈베리파이) 연동판 — 으로 분리한다. 한 저장소, 공용 코어 + 앱 셸 2개.

**Architecture:** 3단계. (1) 공용 코드가 디바이스 모듈을 정적 import 하는 곳을 주입으로 뒤집고 디바이스 배타 파일을 `src/device/` 로 이동. (2) `App.tsx`·`HomeScreen`·`ConversationScreen` 을 변종 2벌로 가르고 `mode` 개념 소멸, babel module-resolver alias 로 `APP_VARIANT` 별 엔트리 선택(transform 시점 그래프 절단). (3) `app.config.js` + prebuild 전환으로 빌드 갈래(이름·bundleId·권한 분기).

**Tech Stack:** Expo SDK 57 / RN 0.74 (legacy root), jest-expo + react-test-renderer, babel-plugin-module-resolver (신규 devDep 1개).

**Spec:** `docs/superpowers/specs/2026-08-10-app-split-design.md`. 스펙 대비 정정 2건 (실측 근거):
1. **EyeAnimation·MicLevelIndicator 는 `src/phone/` 으로 이동하지 않는다.** 공용 화면 4개(BoardView·CharacterView·ProcessingView·CameraScreen)가 EyeAnimation 을 정적 import 한다 — 이동하면 공용→phone 의존이 생긴다. 번들 포함은 디렉터리가 아니라 import 그래프가 결정하므로 제자리에 둬도 폰 번들 절단 목표(piBridge 부재)와 무관하다. 대가: 디바이스 번들에 EyeAnimation 죽은 코드 ~수백 줄이 남는다(렌더 경로 없음, `showEyes=false` 상수). 진짜 제거하려면 공용 화면 4개에 눈 컴포넌트 주입이 필요 — 범위 밖.
2. **"공용 코드에 src/device import 0건" 판정은 1단계가 아니라 2단계 종료 시점.** 1단계에서는 App.tsx·HomeScreen·ConversationScreen 이 아직 안 갈라져 디바이스 모듈을 import 한다.

```tsx
// F1 (device-vitals 스펙 정정 절): 연결 직후 첫 /health 프로브는 wake 스트림
// resume 전이라 멀쩡한 마이크도 mic_ok:false 로 온다. 연결 엣지에서
// MIC_GRACE_MS 동안 micOk:false 를 "모름"으로 강등해 오탐 주황 점을 막는다.
// 5초 폴링이라 grace 만료 후 늦어도 다음 폴에서 실값이 반영된다.
export const MIC_GRACE_MS = 12000;
export function graceHealth(
  health: PiHealth | null, connectedSinceMs: number | null, nowMs: number,
): PiHealth | null {
  if (!health || health.micOk !== false || connectedSinceMs === null) return health;
  if (nowMs - connectedSinceMs < MIC_GRACE_MS) return { ...health, micOk: undefined };
  return health;
}
```
