# Google Cloud TTS API 키 새로 발급받기

VIVA 앱이 말을 할 때 쓰는 목소리는 Google Cloud의 Text-to-Speech(TTS) 서비스에서 옵니다.
이 서비스를 쓰려면 **API 키**라는 비밀번호 같은 문자열이 필요합니다.

이 문서는 **새 Google Cloud 프로젝트를 만들고, 거기서 TTS API 키를 새로 발급받아, 앱에 연결하는 것**까지를 다룹니다.
컴퓨터 전공이 아니어도 순서대로 따라 하면 됩니다. 전체 10~15분 정도 걸립니다.

기존에 쓰던 프로젝트와 키는 이 문서에서 건드리지 않습니다. 그대로 살아 있습니다.

---

## 미리 알아둘 것

- **Google Cloud 프로젝트**란: 구글이 제공하는 서비스들을 담아두는 상자입니다. 결제, 사용량, 키가 이 상자 단위로 관리됩니다.
- **결제 계정 연결이 필수입니다.** 카드를 등록하지 않으면 TTS 서비스를 켜는 것 자체가 막힙니다. 무료 사용량 범위 안에서는 실제로 청구되지 않지만, 등록은 해야 합니다.
- 준비물: 구글 계정, 결제용 카드.

---

## 1단계. 새 프로젝트 만들기

1. 브라우저에서 https://console.cloud.google.com 에 접속하고 구글 계정으로 로그인합니다.
2. 화면 **맨 위 왼쪽**, 구글 클라우드 로고 옆에 프로젝트 이름이 적힌 버튼이 있습니다. 클릭합니다.
3. 팝업 창 오른쪽 위의 **새 프로젝트**를 클릭합니다.
4. 프로젝트 이름에 알아보기 쉬운 이름을 적습니다. 예: `viva-tts`
5. **만들기**를 클릭하고 10초 정도 기다립니다.
6. 생성이 끝나면 다시 맨 위의 프로젝트 선택 버튼을 눌러, **방금 만든 프로젝트를 선택**합니다.

> 중요: 앞으로의 모든 단계는 새로 만든 프로젝트가 선택된 상태에서 진행해야 합니다.
> 화면 맨 위에 표시된 프로젝트 이름이 방금 만든 것과 같은지 단계마다 확인하세요.
> 다른 프로젝트에서 키를 만들면, 키는 만들어지지만 앱에서 계속 오류가 납니다.

---

## 2단계. 결제 계정 연결하기

1. 화면 왼쪽 위의 줄 세 개 아이콘(메뉴)을 클릭합니다.
2. **결제**를 클릭합니다.
3. **결제 계정 연결** 버튼이 보이면 클릭해서 기존 결제 계정을 선택합니다.
   - 결제 계정이 하나도 없다면 **결제 계정 만들기**를 눌러 카드를 등록합니다. 안내에 따라 국가와 카드 정보를 입력하면 됩니다.
4. 연결이 끝나면 결제 화면에 계정 이름이 표시됩니다.

---

## 3단계. Text-to-Speech 서비스 켜기

프로젝트를 만들어도 서비스는 기본적으로 꺼져 있습니다. 직접 켜야 합니다.

1. 왼쪽 메뉴에서 **API 및 서비스** > **라이브러리**를 클릭합니다.
2. 검색창에 `Text-to-Speech` 를 입력합니다.
3. 검색 결과에서 **Cloud Text-to-Speech API**를 클릭합니다.
4. **사용 설정** 버튼을 클릭합니다.
5. 버튼이 **관리**로 바뀌면 켜진 것입니다. 반영에 1~2분 걸릴 수 있습니다.

> **사용 설정** 버튼이 눌리지 않거나 결제를 요구하는 메시지가 뜨면 2단계가 제대로 끝나지 않은 것입니다. 2단계로 돌아가세요.

---

## 4단계. API 키 만들기

1. 왼쪽 메뉴에서 **API 및 서비스** > **사용자 인증 정보**를 클릭합니다.
2. 화면 위쪽의 **+ 사용자 인증 정보 만들기**를 클릭합니다.
3. 목록에서 **API 키**를 선택합니다.
4. 팝업에 키가 표시됩니다. `AIza...` 로 시작하는 긴 문자열입니다. **복사**를 눌러 메모장 등에 잠시 붙여둡니다.
5. 팝업을 닫습니다.

> 이 키는 비밀번호와 같습니다. 카카오톡, 슬랙, 이메일, 깃허브 등에 그대로 올리지 마세요.

---

## 5단계. 키에 제한 걸기

방금 만든 키는 아무 제한이 없는 상태입니다. 누군가 이 키를 손에 넣으면 다른 구글 서비스까지 마음대로 쓸 수 있습니다.
TTS 외에는 못 쓰도록 제한을 겁니다.

1. 사용자 인증 정보 화면의 API 키 목록에서 방금 만든 키 이름을 클릭합니다.
2. **API 제한사항** 항목에서 **키 제한**을 선택합니다.
3. 아래 나타나는 드롭다운에서 **Cloud Text-to-Speech API**만 체크합니다.
4. **애플리케이션 제한사항**은 **없음**으로 둡니다. (이유는 아래 참고)
5. 맨 아래 **저장**을 클릭합니다.

### 애플리케이션 제한사항을 왜 비워두나요

이 앱은 키를 앱 안에 넣어서 씁니다. 그래서 앱 파일을 뜯어보면 키가 보입니다.
원래는 "이 앱에서만 이 키를 쓸 수 있다"는 제한(애플리케이션 제한)을 걸어야 안전합니다.
다만 그 제한을 걸려면 앱의 서명 정보가 필요한데, 개발 중에는 이 값이 자주 바뀌어서 그때마다 앱이 멈춥니다.
그래서 **개발 단계에서는 API 제한만 걸고 애플리케이션 제한은 비워둡니다.**

> 실제 출시 전에는 반드시 애플리케이션 제한을 추가하거나, 키를 서버로 옮겨야 합니다.
> 지금 상태 그대로 스토어에 올리면 키가 외부에 노출됩니다.

## 6단계. 앱에 새 키 넣기

1. 프로젝트 폴더 `viva-merged` 안의 **`.env`** 파일을 텍스트 편집기로 엽니다.
   - 이름이 점(`.`)으로 시작해서 파일 탐색기에서 안 보일 수 있습니다. VS Code 등 편집기에서 열면 보입니다.
2. 아래 줄을 찾습니다.

   ```
   EXPO_PUBLIC_GOOGLE_TTS_API_KEY=(기존 키)
   ```

3. `=` 뒤의 값만 새 키로 바꿉니다. 따옴표나 공백은 넣지 않습니다.

   ```
   EXPO_PUBLIC_GOOGLE_TTS_API_KEY=AIza여기에새키
   ```

4. 저장합니다.

`.env` 파일은 깃(git)에 올라가지 않도록 이미 설정돼 있습니다. 따로 할 일은 없습니다.

음성 테스트용 스크립트 `tts-tester/generate.js` 도 같은 `.env` 를 읽기 때문에, 이 단계 하나로 함께 반영됩니다.

---

## 7단계. 키가 잘 되는지 확인하기

앱을 켜기 전에 명령어 한 줄로 먼저 확인합니다.

1. 터미널(맥: 터미널 앱, 윈도우: PowerShell)을 엽니다.
2. 아래 명령을 붙여넣되, `여기에새키` 부분만 실제 키로 바꿉니다.

```bash
curl -s -X POST "https://texttospeech.googleapis.com/v1/text:synthesize?key=여기에새키" \
  -H "Content-Type: application/json" \
  -d '{"input":{"text":"안녕 비바야"},
       "voice":{"languageCode":"ko-KR","name":"ko-KR-Chirp3-HD-Aoede"},
       "audioConfig":{"audioEncoding":"MP3","speakingRate":1.05}}' \
  | head -c 120
```

3. 엔터를 칩니다.

**성공한 경우** — 아래처럼 `audioContent` 로 시작하는 알 수 없는 문자열이 나옵니다. 이게 음성 데이터입니다. 정상입니다.

```
{"audioContent": "//NExAARAAAAAAAAAAA...
```

**실패한 경우** — `error` 로 시작하는 메시지가 나옵니다. 아래 문제 해결 표에서 해당 메시지를 찾으세요.

---

## 8단계. 앱 다시 시작하기

키는 앱이 켜질 때 한 번 읽힙니다. 앱이 이미 실행 중이었다면 새 키가 반영되지 않습니다.

1. 실행 중인 앱과 개발 서버를 완전히 종료합니다. (터미널에서 `Ctrl + C`)
2. `viva-merged` 폴더에서 아래 명령으로 다시 시작합니다.

```bash
npx expo start -c
```

`-c` 는 이전에 저장해둔 값을 지우고 새로 읽으라는 뜻입니다. 키를 바꿨을 때는 이걸 붙여야 합니다.

3. 앱에서 대화를 시작해 목소리가 나오면 완료입니다.

## 문제 해결

| 화면에 나온 메시지 / 증상 | 원인 | 해결 방법 |
|---|---|---|
| `SERVICE_DISABLED` 또는 `has not been used in project ... before or it is disabled` | 3단계에서 서비스를 켜지 않았음 | 3단계를 다시 하고 1~2분 기다린 뒤 재시도 |
| `API key not valid` | 키를 잘못 복사했거나 앞뒤에 공백·따옴표가 들어감 | 키를 다시 복사해 붙여넣기. `.env` 에 따옴표 없이 |
| `Requests to this API texttospeech.googleapis.com method ... are blocked` | 5단계 API 제한 목록에 Text-to-Speech가 빠져 있음 | 5단계로 돌아가 **Cloud Text-to-Speech API** 체크 후 저장 |
| `requests from this ... are blocked` (referer, android, ios 등이 언급됨) | 애플리케이션 제한이 걸려 있음 | 5단계에서 애플리케이션 제한을 **없음**으로 변경 |
| `voice ... does not exist` | 음성 이름 오타 | `ko-KR-Chirp3-HD-Aoede` 철자 확인 |
| `billing` 이 언급된 오류, 또는 3단계에서 **사용 설정** 버튼이 안 눌림 | 결제 계정 미연결 | 2단계 수행 |
| curl은 성공하는데 앱에서만 소리가 안 남 | 앱이 옛날 키를 기억하고 있음 | 8단계의 `npx expo start -c` 로 재시작 |
| 모든 게 맞는데 계속 실패 | 다른 프로젝트에서 키를 만들었을 가능성 | 콘솔 맨 위 프로젝트 이름이 1단계에서 만든 것과 같은지 확인 후 4단계부터 다시 |

## 이 문서에서 다루지 않는 것

- 기존 Google Cloud 프로젝트와 기존 키의 삭제 또는 정리
- Gemini API 키, Supabase 키 (`.env` 에 함께 있지만 이번 작업과 무관합니다)
- 서비스 계정(JSON 키) 방식. 이 앱은 단순 API 키 방식만 씁니다.
